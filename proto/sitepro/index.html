Luz 0.4.1 beta · Open source, MIT

The design system that disappears.

Luz is a design system in plain HTML, CSS and ES modules, for people who want their site to outlive its framework. It styles the markup you already write. The browser does the rest.

Modular by design

Three layers. Take one, or take them all.

Each package needs the one below it and nothing above it. Adopt a level, stop there, and come back when the project grows.

Why Luz

Most design systems ask you to learn them. Luz asks you to remember HTML.

01

No class required

A button is a <button>. A table is a <table>. Write the element and it arrives finished. A class only adds what HTML cannot say.

02

No script required

Dialogs, popovers and accordions are the browser's own. JavaScript improves the page. It is never the reason the page works.

03

No build required

Two <link> tags and you are live. Use a bundler if you like one. Luz will never ask for it.

What you get

Everything a page needs. Nothing it doesn't.

Your CSS always wins

Everything ships in named cascade layers, and bare elements have zero specificity. Override anything with one plain rule. No !important, no fight.

Works with JavaScript off

Every component is tested twice: once with scripts, once without. The page your reader gets on a bad day still works.

Three modes, one source

Light, dark and high contrast come from the same semantic tokens. Every pair of colors is measured before it ships.

Pay for what you link

One stylesheet per piece. A page that uses the hero and the search loads the hero and the search, and not one byte of the rest.

Tested first, always

Every change starts life as a failing test. If it is in the box, something already tried to break it.

Yours in three knobs

Type base, type ratio, space unit. Turn them and the whole system follows. The brand, and the last word, stay yours.

Kinds of site

One system. Four ways to begin.

The catalog knows the shape of the site you are about to make. Start from the pattern, then make it unmistakably yours.

Landing page

Site header, hero, sections, footer.

Blog or newspaper

Masthead, article, table of contents.

Web application

App bar, dashboard, charts, data views.

Documentation

Docs layout, page rail, pager.

Accessibility

Accessible, and honest about the gaps.

WCAG 2.2 AA is the baseline of every piece. Where Luz falls short, the statement says so in public, with the criterion it fails.

What holds

Tested on every component

  • Keyboard only, with a focus ring you can always see.
  • Reflow at 400% zoom, down to 320 pixels.
  • Forced colors and reduced motion.
  • Contrast measured in the three modes, by the build.

What does not, yet

Known and written down

  • A custom theme is yours to check. The contrast tool is in the box.
  • Screen reader tests are by hand, and listed per release.
  • Luz is in beta: a name can still change before 1.0.

Start in your terminal

One command. It asks before it writes.

It looks at your project first, asks only what it could not tell, shows you the plan and writes nothing until you say yes. Then it checks the result with luz-check.

npm create @luz-ds@0.4.1
Detects
Your stack, your package manager, and whether Luz is already there.
Plans
Every file it will create or change, with the diff, before it touches one.
Checks
Runs luz-check at the end and tells you what is left.

Working with an AI? Tell it to run npx @luz-ds/create@0.4.1 --json. It gets the plan as JSON, and applies it with --confirm once you agree. Use Luz with an AI
