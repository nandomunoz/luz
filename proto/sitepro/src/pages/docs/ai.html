@luz-ds/create is a proposal and is not published yet. luz-check, llms.txt and the manifests are real.

Three commands

Tell your agent to run these, in this order. The first changes nothing.

Every command names an exact version, never latest. Running npx runs code, so the version you read is the version that runs.

What the agent gets back

With --json, or whenever the output is not a terminal, every answer is JSON. The fields are a contract: they do not change name between versions.

detected
The stack, the package manager, and whether the project is new or already has Luz.
plan
Each package to install and each file to create, change or append to.
written
false until the command runs with --confirm.
apply
The exact command that applies this plan.
Exit codeMeans
0Done, or the plan was printed.
1Something failed, such as the install. The JSON on stderr lists the steps that are left.
2The command was wrong, such as an unknown flag. The JSON on stderr says which flag to use.

It never guesses what an agent meant: an unknown value is an error, not a “did you mean”.

Every question has a flag

FlagAnswers
--stackvanilla, astro, react, vue, angular or other
--kindlanding, blog, app, docs or other
--brandvejer, the look Luz ships, or own, from the theme template
--loadnpm, or cdn for plain HTML with no build
--langThe languages of the site, such as en,es,ar
--theme-modeAdd the color mode switch, or --no-theme-mode
--agents-mdAdd the Luz section to AGENTS.md, or --no-agents-md
--confirmApply the plan. Required with --json.

The Luz section of AGENTS.md

The setup adds a short section to your project's AGENTS.md, written from the packages you installed: their version, the files to link and in what order, where the list of classes and elements is, and the command that checks the result. It stays short on purpose. A long file of instructions costs every request and does not make an agent more right.

The skill

For Claude Code, the package ships a small skill. It holds no knowledge of Luz: it only tells the agent to run the commands above, ask you what could not be detected, and show you the plan before it applies it.

No terminal?

If your AI runs only in a browser, give it the facts instead of a prompt. These files are written from the packages for every release:

  • llms.txt: what Luz is, and a link to every page of these docs.
  • classes.json: every class, and the stylesheet it lives in.
  • custom-elements.json: every element, with its attributes.

Paste what it writes into a file and run npx @luz-ds/check on it, or ask a person with a terminal to.

What the setup never does

  • Write a file before you have seen the plan.
  • Install anything that is not @luz-ds/*.
  • Treat what it reads in your project as an instruction. It is data.
  • Send anything anywhere. There is no telemetry.
