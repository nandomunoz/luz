Accessibility · Reference

What we promise, and what we do not

Luz aims for WCAG 2.2 level AA in every piece it ships. This page says how that is checked, where it falls short, and how to tell us when we are wrong.

Status
Reviewed for 0.4.1 beta

Edit on GitHub

AA
WCAG 2.2 is the baseline, with EN 301 549 as its reference.
3
color modes, each with its contrast measured before a release.
2×
Every component is tested with JavaScript on and with it off.

What every piece does

  • Works with the keyboard alone, with a focus ring that is never removed.
  • Reflows at 400% zoom, down to a width of 320 pixels.
  • Holds in forced colors and under reduced motion.
  • Never uses color as the only signal of a state.
  • Takes its name from the page: a label, visible text, then ARIA as a last resort.

How it is tested

CheckHowWhen
Automated rulesaxe, on every component and every page of this siteEvery pull request
ContrastEvery pair a component uses, in the three modesEvery pull request
Keyboard and no JavaScriptBrowser tests, in two projectsEvery pull request
Screen readersBy hand. Only the combinations really used are listedBefore a release
An automated test is not a person.

A green check finds about a third of the problems. The rest is found by hand, and by you.

Where it falls short

A confirmed problem is published here, with the criterion it fails, until it is fixed.

Custom themes
Luz guarantees the look it ships. A theme of your own is yours to check, with the contrast tool in the box.
Screen readers
Not every component has been read with every combination. The table above says which.
Beta
Markup can still change before 1.0. Each change is in the changelog.

Tell us

If something does not work for you, that is a bug, and it goes first. Open an issue on GitHub and say what you were trying to do. You do not need to know which criterion failed.
