Button

The one thing on the page you want people to do. A native button, finished, with no class at all.

Package
@luz-ds/core
File
components/button.css
JavaScript
None
Status

Example

Live · try the keyboardLight

Known issues

None known.

Code

Copy the markup

A <button> needs nothing. Use the class when the element is not a button, or when you need a variant HTML cannot say.

Variants and options

ClassLooks likeUse it for
luz-btnPrimaryThe main action. One per view.
luz-btn--secondarySecondaryEverything else that is still an action.
luz-btn--dangerDeleteAn action that destroys something.
luz-btn--smSmallDense rows and toolbars.
luz-btn--lgLargeThe call to action of a hero.
luz-btn--blockFull widthNarrow screens and forms in a column.

How it works

Luz tells variants apart by meaning, not by class. A button that submits is primary. A button that does not is secondary. You say which one with the type attribute you were already writing.

Without JavaScript

The button has no script. It is the same with JavaScript on or off.

Keyboard and ARIA

Tab
Moves focus to the button. The focus ring is always visible.
Enter Space
Activates it. A link styled as a button answers to Enter only, as every link does.
disabled
Takes the button out of the tab order and lowers its contrast. Avoid it in forms. In a toolbar, aria-disabled="true" keeps it focusable.
aria-pressed
For a toggle. The pressed state has a border as well as a color.

Design

When to use

  • To submit a form, or to do something on the page.
  • To start a task: open a dialog, add a row, send a message.

When not to use

  • To go somewhere. That is a link, even when it looks like a button.
  • For a second primary action. If everything is primary, nothing is.
  • Switched off to stop a form being sent. Leave it on, and when it is pressed, say what is missing.

Do and don't

Writing the content

Two or three words. Sentence case. A verb first: “Save changes”, not “Changes”. Never “Click here”.
