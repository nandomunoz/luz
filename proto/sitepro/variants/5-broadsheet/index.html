Special edition

A design system made of plain HTML, CSS and ES modules goes to press

Three packages that stack. Nothing to install at run time. Works with JavaScript off, and meets WCAG 2.2 AA from the first line.

LUZ arrived this morning in three parts, and none of them asked for anything in return. @luz-ds/tokens holds the design tokens as CSS custom properties, in three colour modes. @luz-ds/core styles the bare HTML elements with no class at all, adds layout objects and 29 components, and keeps its JavaScript optional. @luz-ds/catalog brings 41 site-wide pieces and page patterns, one stylesheet each.

The packages stack: core sits on tokens, catalog on both. Take the first and you have a palette; add the second and your plain HTML already looks finished; add the third and a landing page, a blog, an app or a docs site is a matter of markup.

There are zero runtime dependencies. Switch JavaScript off and the pages still read, still submit, still open. Accessibility is not a supplement sold separately: WCAG 2.2 AA is the baseline. And every change, the editors confirm, starts with a failing test.

Opinion · The editors

Why plain HTML

The browser already ships the button, the dialog, the disclosure and the form. A design system should start there, and mostly stay there.

Every few years the web is told it needs a new layer between the page and the browser. The layer arrives with a build step, a runtime, a dependency tree, and a promise. Then the browser catches up, and the layer stays.

LUZ takes the other bet. A <button> with no class is already a finished button. A <details> already opens. A <dialog> already holds focus. So core styles the bare elements, with no class at all, and asks for markup only when a pattern needs a role the element does not have.

JavaScript, where it appears, only enhances what the browser already does. Switch it off and you lose a convenience, never the page. That is why the modules are plain ES modules you can load without a bundler, and why there are zero runtime dependencies to audit.

None of this is nostalgia. WCAG 2.2 AA is the floor, size ceilings are kept, and every change begins as a test that fails. Plain is not the absence of rigour. It is where the rigour goes.

Start with what the browser already does. Then stop adding.
