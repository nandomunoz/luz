The marquee stops while the pointer is over it or a link has the focus, and it stays still when the reader asks for reduced motion. LUZ ships no logos: the marks here are drawn for the example, and the names are made up.

Known issues

With scroll, on a touch screen there is no hover, so only focusing a link stops the marquee. WCAG 2.2 success criterion 2.2.2 (Pause, Stop, Hide) asks for a way to pause moving content that lasts more than five seconds, and the marquee has no button. That is why the still row is the default: use scroll only where the band is a decoration and every link is also somewhere else on the page, or do not use it.

LUZ ships no brand logos: everything it serves is MIT, and a logo is not. The logos are yours, and so is the right to show them.

Code Design

Code

Copy the markup

A <luz-showcase> around a <ul> of links. Each link holds a decorative <svg> and the name in a <span>. Link components/showcase.css of @luz-ds/catalog after core.

HTML 
<luz-showcase>
  <ul>
    <li>
      <a href="https://greenleaf.example/" title="Greenleaf: a gardening journal">
        <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5"
          stroke-linecap="round" stroke-linejoin="round" aria-hidden="true" focusable="false">…</svg>
        <span>Greenleaf</span>
      </a>
    </li>
    <!-- one li for each site -->
  </ul>
</luz-showcase>

For the marquee, add scroll and write the list twice. The copy is aria-hidden="true" and each of its links has tabindex="-1".

HTML 
<luz-showcase scroll>
  <ul>
    <li><a href="https://greenleaf.example/"><svg aria-hidden="true">…</svg><span>Greenleaf</span></a></li>
    <li><a href="https://tidewater.example/"><svg aria-hidden="true">…</svg><span>Tidewater</span></a></li>
  </ul>
  <ul aria-hidden="true">
    <li><a tabindex="-1" href="https://greenleaf.example/"><svg aria-hidden="true">…</svg><span>Greenleaf</span></a></li>
    <li><a tabindex="-1" href="https://tidewater.example/"><svg aria-hidden="true">…</svg><span>Tidewater</span></a></li>
  </ul>
</luz-showcase>

Variants and options

Tag, attribute or propertyEffect
<luz-showcase>
Around a native list of links. The links sit in a row that wraps, centred, in small bold sans text. A tag that no script defines: no class, no role of its own
scroll
On the tag, a boolean attribute: the row becomes a marquee that loops. Write the list twice, the copy with aria-hidden="true" and its links with tabindex="-1". Without scroll the copy is never shown
--luz-showcase-duration
On the tag, how long one loop takes. The default is 40 s. Give a longer list more time, so it moves at the same speed
title
On a link, optional: the name and one line about the site. It is the browser’s tooltip and is not read as the name of the link

How it works

CSS from components/showcase.css of @luz-ds/catalog. No JavaScript: <luz-showcase> is a tag that no script ever defines.

  • The list is a native <ul>, so a screen reader says how many sites there are. The logo is an <svg aria-hidden="true"> or an <img alt=""> before the name, and the name is the name of the link.
  • The logo is 1.5em square and does not shrink. LUZ gives it a size, not a drawing: an <svg> sets its own fill or stroke, and with currentColor it takes the colour of the link.
  • A link is quiet, in the secondary text colour, and takes the primary one under the pointer and with the keyboard focus. It never wraps its name: the row wraps between links.
  • With scroll each list moves by its own width, so the loop has no seam. The band hides what overflows and fades at both ends.
  • The copy is not inert: a pointer can still click a link in it, while the keyboard and a screen reader meet each link once.
  • The marquee stops while the pointer is over it or a link has the focus. Under reduced motion and on paper it is the still row again, and the copy is not shown.
  • In a right-to-left page the marquee runs the other way.

Without JavaScript

Nothing changes: there is no script, and the marquee is CSS.

Keyboard and ARIA

  • Tab: moves through the links in source order, each once. The links of the copy have tabindex="-1".
  • Enter: follows the link, as any link.
  • Name: the text of the <span>. The <svg> is aria-hidden="true", and title is not read as the name.
  • The copy: aria-hidden="true" hides it from a screen reader. Do not use inert, which would also stop the pointer.
  • Target: a link is at least --luz-control-md (36 px) high, over WCAG 2.5.8’s 24 px.
  • Language: a name in another language than the page carries its own lang, on its <span>.
  • Not tested with a screen reader.

Design

When to use

Use it to show who uses, buys, sponsors or backs what the page is about, when the names are the proof: “Built with LUZ”, the customers of a product, the sponsors of an event, the partners of a school.

  • Use the still row. It is the default, and every name can be read without waiting for it.
  • Use scroll only when the band is a decoration and every link is also elsewhere on the page.

When not to use

Do not use it for the links of the site itself, for people’s profiles or for a gallery of work.

  • For the site’s links, use site-footer or the navbar.
  • For profiles and feeds, use social links.
  • For what customers say, in their words, use a card with a quote.
  • Do not show a site, a company or a person that has not agreed to it.

Do and don't

Writing the content

The name is the site’s own, as it writes it, in one to three words. Say what it is in the title if a reader may not know it.

  • Write “Greenleaf”, not “Visit Greenleaf” and not “Logo of Greenleaf”: the link is a name, not a call to action.
  • Keep the capitals the site uses, and put a lang on a name in another language.
  • The title is one line: the name, a colon and what it is. It is a help for the pointer, so nothing a reader needs may be only there.
  • Show the sites you can name and that have said yes. Five to ten read as a band; more, and the row is a wall.
